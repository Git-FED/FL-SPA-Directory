# INSTALL — Setting Up Every Surface

FED-SPA has nothing to install in the usual sense — no package manager, no dependency step, no build chain beyond each platform's own toolchain. That is the point of the no-backend / no-third-party constraints: clone, open, run. This page covers every surface, plus the admin tooling for the annual refresh.

The user-facing behavior of each surface is [USAGE.md](USAGE.md); what CI checks and how packages are produced is [BUILD.md](BUILD.md); shipping the files is [DEPLOYMENT.md](DEPLOYMENT.md).

## Requirements at a glance

| Surface | You need | First run |
|---|---|---|
| Web PWA | any browser + a static file server | instant |
| Extension | Chrome/Edge/Brave etc. (MV3) | load unpacked |
| Android | Android Studio + JDK 17 | open → run |
| Android Auto | Android Studio + JDK 17 | open → run |
| Watch | Android Studio + JDK 17 | open → run |
| iOS | Xcode 15+, macOS | open → run |
| Admin scripts | Python 3.8+ (stdlib only), Node 16+ (native crypto) | nothing to install |

## Web (PWA)

```
cd web
python3 -m http.server 8080
```

Open `http://localhost:8080`. That's the whole setup.

- No bundler, no `npm install`, no env vars — the app is vanilla HTML/CSS/JS reading `web/data/licensed.json` and `web/data/unlicensed.encrypted.json`.
- **Do not open `index.html` via `file://`** — the data files are fetched, and `file://` blocks fetches in every modern browser. A static server is required; any one will do.
- Install as an app: browser menu → *Install app* / *Add to Home Screen*. The service worker (`js/service-worker.js`) precaches the shell and the current release's data for offline use.
- The PWA also runs from any static host: GitHub Pages, S3, a directory server — see [DEPLOYMENT.md](DEPLOYMENT.md).

## Browser extension

1. Open `chrome://extensions` (or your Chromium browser's equivalent).
2. Enable **Developer mode**.
3. **Load unpacked** → select the `extension/` directory.
4. Pin it if you like; the badge activates when you visit a domain matching a listed establishment.

Notes:

- Manifest V3; no remote code, no network permissions — it is offline data + a badge, deliberately.
- Bundled data lives in `extension/data/`. If you just changed source data, re-run `python3 admin_scripts/generate_public_files.py` **before** reloading, or the extension's copy will drift (CI's drift check catches exactly this).
- Options page: subscriber code storage (opt-in), data version display, links to the portal and repo.

## Android / Android Auto / Watch

Each is a self-contained Gradle module. In Android Studio: **File → Open** → select `android/`, `android_auto/`, or `watch/` respectively. Gradle sync pulls exactly two first-party dependencies per module: `androidx.core:core-ktx` and `androidx.appcompat:appcompat` — nothing else, ever.

```
android/            ai.ninjatech.fedspa          minSdk 26, deep link fedspa://parlor/<license>
android_auto/       ai.ninjatech.fedspa.auto     licensed-only, voice-search entry
watch/              ai.ninjatech.fedspa.watch    licensed-only, glanceable rows
```

Requirements: Android Studio (Hedgehog or newer comfortably fits AGP 8.2.2), JDK 17 (bundled with recent Studio versions), an emulator or device on API 26+.

Notes:

- Data is bundled at `app/src/main/assets/data/` — regenerate with the fan-out script after any source-data change.
- The Android manifest declares **no INTERNET permission**. If a build of yours asks for network, something is wrong with the checkout.
- The watch module installs on any Android device for testing; its UI is simply tuned for small round/square screens.
- Build from the CLI if you prefer: `./gradlew assembleDebug` inside the module directory.

## iOS

Open `ios/FedSpa.xcodeproj`… with one caveat, documented in `ios/README.md`: the committed project file is a structural placeholder (`project.json`) describing the source tree, because a full `.xcodeproj` bundle is generated by Xcode on first open. The recipe — create the project, add the listed sources, set the bundle id `ai.ninjatech.fedspa`, add the asset catalog — is written out step by step in `ios/README.md`, and takes about two minutes in Xcode 15+.

Requirements: macOS, Xcode 15+, no Swift Package Manager dependencies — CryptoKit and CommonCrypto come with the SDK.

## Admin scripts (annual refresh tooling)

Nothing to install. The scripts run on stock runtimes:

```
python3 admin_scripts/validate_schema.py          # stdlib only
python3 admin_scripts/generate_public_files.py    # stdlib only
node admin_scripts/encrypt_unlicensed.js          # Node's native crypto
bash admin_scripts/merge_and_encrypt.sh           # orchestrates all of the above
python3 admin_scripts/scrape_mqa.py               # portal fetch helper (SCRAPE=1 path)
```

Requirements: Python 3.8+ (stdlib only — no pip installs), Node 16+ (native `crypto` module only — no npm installs), and `bash`. If any of these ask you to install a dependency, your checkout is wrong.

## Verifying a fresh checkout

Two commands, run from the repo root, confirm the tree is sound:

```
python3 admin_scripts/validate_schema.py
python3 admin_scripts/generate_public_files.py && git status --short
```

The first validates the dataset against `data/meta/schema.json`. The second regenerates every surface's bundled data; `git status` should come back **clean** if the checkout is consistent (this is the same drift check CI runs on every push and PR).

## Troubleshooting

- **Web app shows an empty list** — you opened it via `file://`. Serve it (see above), or check that `web/data/licensed.json` exists and matches the source data (run the fan-out script).
- **Extension badge never fires** — the bundled data in `extension/data/` is stale or missing; re-run the fan-out script and reload the extension. Also confirm you're on a domain actually in the dataset (coverage today is intentionally small — see [wiki/Data-statistics.md](wiki/Data-statistics.md)).
- **Unlock fails with "wrong code"** everywhere — the bundled envelope is stale relative to a rotated code; both ship together in a release, so re-pull the latest data tag.
- **Android build errors about missing classes** — a dependency beyond core-ktx/appcompat was added somewhere; that's a constraints violation in the checkout, not a Gradle problem to work around.
- **Xcode complains about missing files** — you skipped the first-open recipe in `ios/README.md`; the project file is generated, not committed.
